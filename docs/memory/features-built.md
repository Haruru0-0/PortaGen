## Design pass 2 (accessibility, landing, editor, dashboard)
- Accessibility: PixelInput/PixelPasswordInput link labels to inputs (`useId`), `aria-invalid` red border, forms use `noValidate` with `role="alert"` errors; icon-only buttons have `aria-label`; 40px+ targets; `.readable :focus-visible` solid 3px ring; `.dashboard-pixel-button` hover/active press states.
- `PixelButton asChild` (Radix Slot) lets a `Link` be the button (no `<a><button>`); landing uses it everywhere.
- Landing/privacy: one brand name (PORTAGEN), no fake social tiles, deterministic skyline heights (no `Math.random` hydration errors), back-to-home links on auth and privacy.
- Editor: tab strip scrolls horizontally below `lg` with tablist roles, "Preview ↓" floating jump button + "Back to the controls" link, mobile starts in mobile preview, Theme tab sections are collapsible `<details>`.
- Dashboard: header title follows the page, no fake "PLAYER_ONE"/example.com identity, checklist rows are links, pages share `max-w-5xl`, Edit is primary and Delete red outline. (The Assets page this pass also touched was later removed.)

- **2026-11-11 Deleting wallpapers and files:** `FileUpload` has an optional `onRemove` (shown inside the upload box next to CHANGE FILE while an image is shown). It is wired for the desktop wallpaper, lock screen wallpaper, the mobile wallpaper (label USE DESKTOP WALLPAPER), menu bar icon, desktop GIF, the two mobile widgets and the icon edit dialog (it calls `POST /api/icons/update` with `clearImage: true`, so the icon shows the placeholder again; the add dialog's button only drops the picture chosen so far, nothing being saved yet; deleting a whole icon from the Icons tab still leaves its image file in UploadThing); each clears that portfolio's file or link through the existing route so the default shows again, then deletes the uploaded file too (UploadThing and database) through `useAssetCleanup` (`src/hooks/use-asset-cleanup.tsx`). Before deleting it asks `GET /api/assets/usage?assetId=` (backed by `src/lib/asset-usage.ts`, which also feeds the library picker's `usedIn`) whether any other portfolio setting or icon still uses the file; if so a "FILE IS USED ELSEWHERE" dialog names them and deletes only if confirmed (declining keeps the file, the setting stays cleared); if the check fails the file is kept. Link-only values now also show in the uploader preview so they can be removed. The "Select from library" picker (`asset-picker.tsx`) has a delete button on every item with a confirmation that lists the portfolios using the file (`usedIn`, computed in `GET /api/assets` from the desktop settings, lock screen settings and icons tables); confirming calls `DELETE /api/upload/[fileId]`, which removes the file from UploadThing and the row, and the foreign keys (`on delete set null`) put those portfolios back to their default. Files uploaded before UploadThing are only removed from the database, not from Google Drive. `tsc` and `yarn build` pass; not clicked through with a real account.
